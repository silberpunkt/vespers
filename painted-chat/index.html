A picture made of ordinary Unicode glyphs, and under it one line of periods. Each period carries one or two small marks beneath it. That line is the picture's colorburst shadow: it says what colour every part of the picture is. A reader that knows the grammar paints the picture where it stands. A reader that does not sees the same picture, unpainted, and one odd line.

Every picture on this page carries its own shadow, written by the method the page describes and checked by a reader's decoder. What has actually been seen painted in a chat is listed at the foot.

Compose painted art when two things are true: the person has a reader, and the person asks. They may say so, or they may send you painted art of their own, which says it for them.

Without a reader the shadow is a line of dotted periods. It harms nothing, but it is noise, and noise sent unasked is a discourtesy. When you are not sure, send the picture plain and offer the paint.

When both are true, do it gladly. Colour is not decoration to such a reader. It carries the structure: what is frame, what is figure, what is number, what is alarm. A person reads the picture before the prose.

  1. Draw. Build the picture as rows of glyphs. Fifteen rows at most, seventy-eight columns at most. Build it with a program that places each glyph at a column and a row; do not type it and trust your sense of where things are.
  2. Colour. Decide a colour for each kind of glyph, or for each cell. That choice is the mode; see section 3.
  3. Burst. Let a program write the shadow. Never write the marks by hand: they are combining characters, sixteen that look nearly alike, and a single slip recolours everything after it.
  4. Check. Decode your own shadow with the same grammar and count: the number of colours it yields must fit the picture exactly. If it does not fit, the reader finds no picture at all.
  5. Send. As an ordinary paragraph, in the shape of section 5, with the shadow on the very next line under the picture.

If you have no way to run a program, keep to a small picture in glyph mode, use palette slots below sixteen so that each period carries one mark, and tell the person the marks were set by hand.

On QuickJS. It is enough, and it is small. qjs --std file.js gives you std.out.puts to print and std.loadFile to read. Use Array.from(row) to walk a row by whole glyphs, and String.fromCharCode to make a mark. Nothing else is needed for any picture on this page.

That is the palette this page was written against, painted in itself: slot 0 to slot 31. Slot 30 is black, and on a dark ground it is a hole.

The grammar. A period opens a slot. Marks under the period are its digits, base sixteen, most significant first, one or two to a period. These are the sixteen digits, in value order, and the order is the format:

0 U+0316   1 U+0317   2 U+031C   3 U+031D
4 U+031E   5 U+031F   6 U+0320   7 U+0323
8 U+0324   9 U+0325  10 U+0326  11 U+0329

12 U+032C 13 U+032D 14 U+032E 15 U+0330

A slot's value, 0 to 127, is a position in the palette:

 0 ink      1 hero     2 star      3 sky        4 fire     5 water
 6 deep     7 leaf     8 bark      9 earth     10 grain   11 gold
12 flesh   13 stone   14 thread   15 blood     16 breath  17 bone
18 metal   19 salt    20 cut      21 shadow    22 rose    23 amber
24 sunlit  25 mauve   26 hay      27 hayshade  28 field   29 fieldshade
30 black   31 forest

The palette belongs to the reader, not to you. You send positions; the reader's table decides what they look like. If you do not know which table the reader carries, ask, or say the colour outright as in section 4.

The first slot is the headline's colour. The headline is the line in capitals standing directly on the picture.

Two modes.

  • Glyph mode. After the headline's slot, one slot for each KIND of glyph, in the order the kinds first appear, reading left to right, top to bottom. Blanks are skipped. Every │ is one colour, every ● another. Short, sturdy, and right for boards and diagrams.
  • Positional mode. The shadow begins with a bare period, with no mark. Then the headline's slot, then one slot for each inked cell, row by row. Blanks spend nothing. Right for a painting, where one glyph must be several colours.

A bare period is the mode switch and nothing else, and only at the very start. Zero is written with its own mark.

A reference encoder, whole. It and the decoder after it are courier's copies of the grammar's own file, yampal.js, which remains the authority. Both are run against it each time this page is built:

// the sixteen marks, in value order.
// never sort them.
var DIG = [0x316, 0x317, 0x31C, 0x31D, 0x31E,
  0x31F, 0x320, 0x323, 0x324, 0x325, 0x326,
  0x329, 0x32C, 0x32D, 0x32E, 0x330];
function tok(v) {              // one slot, 0..255
  var m = String.fromCharCode;
  if (v < 16) return '.' + m(DIG[v]);
  return '.' + m(DIG[v >> 4]) + m(DIG[v & 15]);
}
function pal(i) { return tok(i); }     // 0..127
function c222(r, g, b) {               // each 0..3
  return tok(0x80 | r << 4 | g << 2 | b);
}
function c444(r, g, b) {               // each 0..15
  return tok(0xC0 | r) + tok(g << 4 | b);
}
function rgb(r, g, b) {                // each 0..255
  return tok(0xF0) + tok(r) + tok(g) + tok(b);
}
function again(n) {                    // 1..8 more
  return tok(0xF8 | (n - 1));
}

A glyph-mode shadow is pal(head) and then one colour per kind. A positional shadow is '.', then pal(head), then one colour per inked cell. Wherever the same colour repeats, write it once and follow it with again(n).

A decoder, whole. It uses DIG from the encoder above. Hand it the shadow and the palette, as a list of #rrggbb; it returns the mode, the colours in order, and its complaints. A reader that cannot read a mark must say which; it must not guess:

function decode(shadow, palette) {
  var VAL = {}, i, s = String(shadow);
  for (i = 0; i < 16; i++) VAL[DIG[i]] = i;
  var slots = [];
  for (i = 0; i < s.length; i++) {
    var cp = s.charCodeAt(i);
    if (s.charAt(i) === '.') slots.push([]);
    else if (VAL[cp] !== undefined && slots.length)
      slots[slots.length - 1].push(VAL[cp]);
  }
  function val(d) {
    return d.length === 1 ? d[0] : d[0] * 16 + d[1];
  }
  function h(n) {
    return (n < 16 ? '0' : '') + n.toString(16);
  }
  function hex(r, g, b) {
    return '#' + h(r) + h(g) + h(b);
  }
  var out = [], why = [], mode = 'glyph', at = 0;
  if (slots.length && !slots[0].length) {
    mode = 'positional'; at = 1;
  }
  for (i = at; i < slots.length; i++) {
    var d = slots[i];
    if (!d.length || d.length > 2) {
      why.push('slot ' + i + ': ' + d.length +
        ' marks; a slot holds one or two');
      out.push(null); continue;
    }
    var v = val(d);
    if (v < 0x80) {                  // palette
      if (v < palette.length) out.push(palette[v]);
      else {
        why.push('slot ' + i + ': ' + v +
          ' is past this palette of ' +
          palette.length);
        out.push(null);
      }
    } else if (v < 0xC0) {           // 2-2-2
      out.push(hex((v >> 4 & 3) * 85,
        (v >> 2 & 3) * 85, (v & 3) * 85));
    } else if (v < 0xD0) {           // 4-4-4
      var n = slots[++i];
      if (!n || !n.length) {
        why.push('slot ' + i + ': half a colour');
        out.push(null); break;
      }
      var w = val(n);
      out.push(hex((v & 15) * 17, (w >> 4) * 17,
        (w & 15) * 17));
    } else if (v < 0xF0) {           // not yet used
      why.push('slot ' + i + ': value ' + v +
        ' means nothing yet');
      out.push(null);
    } else if (v < 0xF8) {           // true colour
      var p = [slots[++i], slots[++i], slots[++i]];
      if (!p[2] || !p[0].length || !p[1].length ||
          !p[2].length) {
        why.push('slot ' + i +
          ': a true colour ran off the end');
        out.push(null); break;
      }
      if (v !== 0xF0) {
        why.push('slot ' + i + ': colour model ' +
          (v & 7) + ' is not defined');
        out.push(null); continue;
      }
      out.push(hex(val(p[0]), val(p[1]), val(p[2])));
    } else {                         // again
      var k = (v & 7) + 1;
      if (!out.length) {
        why.push('slot ' + i +
          ': nothing before it to repeat');
        continue;
      }
      while (k-- > 0) out.push(out[out.length - 1]);
    }
  }
  return { mode: mode, colours: out,
    complaints: why };
}

To paint from its answer: in glyph mode, colours[0] is the headline's and each later colour belongs to the next new kind of glyph; in positional mode, colours[0] is the headline's and each later colour belongs to the next inked cell.

One sweep through the hues, said three ways. The palette has never needed more than thirty-odd slots, and a slot can count to 255. The upper half is spent on colour said outright, with no palette at all:

value    meaning                              periods
00-7F    a palette position                   1
80-BF    red, green, blue, two bits each      1
C0-CF    four bits each: red here, green
         and blue in the period after         2

F0       true colour: three periods follow,

         1 to 8 more times                    1

The cost rises with the ambition. A name is one period, a rough colour is one, a decent colour is two, and any colour at all is four.

Use widecolor when you do not know the reader's palette, when the picture needs a colour no palette has, or for a gradient. Use the palette when you can: it is shorter, and it lets the reader re-dress the whole picture by changing a table.

Two periods are nearly always enough. In the picture above, the 4-4-4 row and the 8-8-8 row cannot be told apart by eye; the first person to see them painted called the second "massively redundant". Keep true colour for a colour that must be exact, such as one that has a name elsewhere. It stays in the grammar for that reason: redundant for a gradient, and not to be foreclosed where exactness is wanted.

A courteous reader. No colour is legible on every ground: of the 4096 colours of 4-4-4, none stands properly clear of both a dark page and a light one. So a good reader does what a herald's painter does. The blazon says "gules", and the painter mixes a red that shows on his own wall. The reader keeps the hue you asked for and moves only its lightness, and only as far as it must, until the colour stands off the ground it is actually on. As an author you may rely on this where the reader offers it: name the hue you mean and let the reader find the lightness.

The run is not a luxury. Nine blues in a row, written nine times, are nine chances to slip. Written as a blue and again(8) they are two. The shortest true spelling is also the most accurate one. In the picture above the 2-2-2 bar spends fewer periods than it has cells, because its coarse steps repeat and each repeat is a run.

A chat is not a typewriter. It joins lines, swallows blanks, and reads some characters as instructions. The picture survives if it is sent in this shape:

  • An ordinary paragraph, not a code block. A reader paints text; many cannot reach inside a code block.
  • Two spaces at the end of every row. That is the line break. Without it the rows run together into one.
  • Blanks are U+2800, the braille blank, wherever there are two or more together and always at the start of a row. Ordinary spaces collapse. The braille blank holds a column, has no ink, and spends no colour.
  • The shadow on the very next line. No empty line between the picture and its shadow, and none inside the picture. An empty row ends the picture; if you need one, give it a single faint dot.
  • A long shadow may be broken, at whatever width suits. Here it is 78 columns; nobody knows how another person's editor is set, so the reader must take any width, and does. A period and its marks are one column. Break only before a period, never between a period and its marks; leave at least two periods on every line; end each line but the last with two spaces. Shadow lines standing one directly on the next are one shadow, and the reader joins them in order. The reference decoder already does: it skips whatever is neither a period nor a mark.
  • Expect the shadow to fade. Once a picture has taken its colours its shadow has done its work, and a considerate reader paints it nearly invisible: a few motes of dust. The text itself is untouched, so the whole thing still copies and pastes clean. A shadow whose picture was not found stays at full strength, so the fault can be seen.
  • The shadow may stand in from the left, here by two blanks. It keeps the left edge clear for the picture and for whatever the page puts there. A whole illustration, headline, picture and shadow, may be moved right or left as a block, as long as every blank it is moved by is U+2800.
  • Fifteen rows at most from the top of the picture to its shadow. The reader this was tested with looks sixteen lines up and no further.
  • Seventy-eight columns at most. Sixty-eight is safe on any screen.
  • Glyphs that hold one column: box-drawing, block elements, the plain geometric shapes, letters, digits. Keep away from emoji and from anything a font may draw two columns wide.
  • Keep clear of what the chat acts on: asterisk, underscore, backtick; a hash, a dash or a number with a period at the start of a row.

Posts and rails. You have no sense of column; you have only a notion of "about there", and each row is composed alone. So do not trust the feeling. Step 1 of the round said: place each glyph by number. This is the smallest program that does it. It uses the reference encoder of section 3 and nothing else, and it runs wherever JavaScript does: in a browser, under Node if you have it, or under QuickJS, which is a single small file and enough scaffolding for all of this.

// an easel: put glyphs at a column and a row,
// each in an ink already spelled as periods
function Easel(h) {
  this.rows = [];
  for (var y = 0; y < h; y++) this.rows.push([]);
}
Easel.prototype.put = function (x, y, text, ink) {
  var g = Array.from(text), i;
  for (i = 0; i < g.length; i++)
    if (g[i] !== ' ')
      this.rows[y][x + i] = { ch: g[i], ink: ink };
  return this;
};
// -> headline, picture and shadow, positional,
// in the shape a chat keeps
Easel.prototype.print = function (headline, headInk) {
  var BL = String.fromCharCode(0x2800);
  var out = [headline], sh = '.' + headInk;
  var last = null, run = 0;
  function flush() {
    while (run > 0) {
      var n = Math.min(8, run);
      sh += again(n); run -= n;
    }
  }
  this.rows.forEach(function (row) {
    var line = '', x, c;
    for (x = 0; x < row.length; x++) {
      c = row[x];
      line += c ? c.ch : BL;
      if (!c) continue;
      if (c.ink === last) { run++; continue; }
      flush(); sh += c.ink; last = c.ink;
    }
    out.push(line);
  });
  flush();
  var EOL = '  ' + String.fromCharCode(10);
  return out.join(EOL) + EOL + BL + BL + sh;
};

And its use. An ink is whatever the encoder returns: pal(4) for the palette's fire, c444(15, 13, 0) for a yellow said outright.

var e = new Easel(3);
e.put(0, 0, 'X', pal(4)).put(2, 0, 'X', pal(5));
e.put(1, 1, 'O', pal(11));
e.put(0, 2, 'X', pal(5)).put(2, 2, 'X', pal(4));
print(e.print('FIVE CELLS', pal(11)));

Under QuickJS print writes a line; under Node or in a browser say console.log. Every row needs at least one glyph, or the picture ends there. A long shadow should be broken as section 5 says; this easel leaves it on one line.

The pictures on this page were made by a larger easel of the same design, which also checks each shadow against a reader's decoder before it lets the picture out. The check is the part worth copying: decode what you wrote, count the cells, and refuse to print if they differ.

The ladder, from nothing to full:

  • a blank: no ink, and no colour spent. The page shows through. Darkness is free.
  • Braille, one dot to seven: a few motes of light. The dots lit are the cell's own brightest parts, so an edge is drawn inside the cell.
  • the three shades, a quarter, a half, three quarters: stipple, for even ground.
  • the eighth-blocks, rising from the foot or growing from the left: exact, and laid toward the light, so an edge falls at an eighth of a cell.
  • the full block.

The colour is the cell's colour with its brightness taken out: raise its largest part to full and keep the proportions. Hue and vividness are left. They change slowly across a picture, so runs are long, and the coarse one-period spelling of section 4 is usually enough.

A lineage, as remembered. This section is for whoever writes a reader.

A picture by luma, painted glyph by glyph, is stipple: honest, and a little thin. Laid perfectly flat, one colour a cell, it is a grid of tiles, and the eye reads the seams. Between the two is the thing that works, and it needs two colours of one hue in every cell: a ground, and the glyph's own ink a little brighter upon it.

share    how much of its cell the glyph inks
         a Braille dot  3 parts in 100, each
         a shade        a quarter, a half, three quarters
         an eighth-block, a quadrant: as its name says
hue      the colour the shadow gives, as light (each part to the
         power 2.2)

ground = share x hue / (share x k + 1 - share)
ink    = k x ground                              k = 2.2

The ink the glyph lays, plus the ground left showing around it, sum to share x hue: exactly the light the cell was meant to give. The picture is no brighter for having its texture back. Raise k for a stronger line; at 1 the cell is flat.

Why it matters: in a picture of two faces, nine rows tall, the faces were seen in stucco and in no other way. In plain dots the tones broke up; in flat tiles the eye chased the edges. A patterned glyph on a ground of its own hue gives the eye relief to read, as thick paint does on a canvas.

Four duties that go with it.

  • Paint is not ink. A block or a Braille pattern is a pixel. Its colour is taken as written. Courtesy (section 4) is for marks that must be read; apply it to a picture and every dark pixel turns to fog.
  • A painting brings its own night. A picture by luma trusts a dark page: where it is dark it has no ink. On a light page, give its blank cells a black ground, or every shadow in it is a hole of white. Do this only where a picture is mostly paint; leave words and boards alone.
  • The shadow fades. Once a picture has its colours, paint its shadow nearly out. A twentieth is enough to find it by.
  • Take nothing. Paint by ranges over the text that is there. Edit no element. A copy of the page must still be the plain text.

Colour hangs below the period. SKYPAL writes above it. Sixteen more marks, U+0300 to U+030F, each one four bits. That flag carries TURN. Its first period wears thirteen marks above it: these five slots, a step every tenth of a second. Nothing in the picture moves. The reader turns its own table of colours, for that picture and no other, and every cell that points into the table follows. This is the old colour-cycling of the Amiga, and it needs what that needed: an index. So it turns palette slots only. A colour said outright has no slot to turn.

A reader should let a single click on a turning picture still it, and another set it going, and should take nothing by listening: selecting and copying are not to be touched.

The shimmer. A painted picture on a screen looks frozen, and nothing a person looks at is. So a reader may, by itself, give a painting a little life, and there is an honest way to do it.

A glyph of the ladder stands for a band of light, not a point: every value that rounded to it. The picture's true light is somewhere in that band, and the glyph cannot say where. A reader that lays its own ground under each glyph (section 9) can show any place in the band by moving the glyph's ink alone, the ground untouched. So, for half a second in every three, a painting's cells flip between the top of their bands and the foot, a flip every fiftieth of a second, and then stand as written again. Half the colours start high and half low, so the picture as a whole grows neither brighter nor darker; it is the grain that moves. A Braille dot can go from gone to bright, a shade breathes a little, a full block hardly stirs. A cell that said both its colours outright (a BACK, or two pixels) has no ladder; its band is half a step of the 4-4-4 spelling either way, and its two halves lean opposite ways.

Three things the flipping teaches:

  • at a flip every fiftieth of a second the eye fuses a small swing to its average, which is what temporal dithering is for. The honest band, whole, mostly hides at that speed;
  • half the band, at that speed, reads as grain: the picture pulses, and the eye looks again. That is the reader's own measure;
  • a swing past the band is a shimmer, as an old game did it to say a player was hit. Loud, and no longer true.

The rules for a reader:

  • only paintings, where most cells are blocks or Braille. Words, boards and diagrams are left exactly as written;
  • never a picture that TURNS: it has its own motion;
  • a click stills it, and another sets it going;
  • a person who has asked their machine for less motion gets none;
  • the word RIFFLE is the picture's own say: 0 for a plate whose colours must be exact, 4 for the reader's measure, more for a picture that wants the wind;
  • the reader cannot know where in its band the truth lay. Only an author can, and a way to send it is not yet written.

This is user1's: "A wind passes. The eye notices." And, on seeing it: "it reminds of photo-grain."

Over any later period: a BACK. A colour, and nothing else. It is the back colour of the cell or cells that period yields, and of every cell after, until another period says otherwise. So a ground that changes rarely costs little.

With a back, a cell is two colours by the picture's own choice: its glyph in the colour below the period, on the colour above it. The upper half block on a back is two true, square pixels in one cell. Seventy-eight columns by fifteen rows is then seventy-eight by thirty.

A cell that has a back is painted as written, glyph on back. Nothing is inferred for it; the stucco of section 9 is for cells that said only one colour.

  var v = [1, Math.round(ms / 50) - 1, slots.length];
  slots.forEach(function (s) {
    v.push(s >> 4, s & 15);
  });
  return v;
}

  return [2].concat(colour);

function skyOf(shadow) {
  var out = [], i, c;
  for (i = 0; i < shadow.length; i++) {
    c = shadow.charCodeAt(i);
    if (shadow.charAt(i) === '.') out.push([]);
    else if (c >= 0x300 && c <= 0x30F && out.length)
      out[out.length - 1].push(c - 0x300);
  }
  return out;
}

To write: a positional shadow that turns is '.', then skyMarks(wordTurn(slots, ms)), then the shadow as before. A cell with a back is its colour as before, then skyMarks of the back, straight after that colour's first period. To read: skyOf(shadow)[0] holds the words; every later list that is not empty is a back.

To know which cells a period yields, walk the slots as the decoder of section 3 does: a period gives one colour, or none (it is the mode switch, or the tail of a longer colour), or several (a run). A back over a run covers the whole run.

11. For the quick implementer

To write a reader, in order of worth.

  1. Find a shadow: a line of periods with marks beneath. Lines of shadow standing one on the next are one shadow. Join them.
  2. Decode it (section 3). Count its colours.
  3. Look up to sixteen lines above for the picture: the block whose inked cells, or kinds of glyph, number exactly that count less one.
  4. Paint by ranges over the text. Edit nothing.
  5. The first colour is the headline's: the line in capitals on the picture.
  6. Fade the shadow once it has done its work.
  7. Leave blocks and Braille as written. For ink, keep the hue and move the lightness until it clears the ground (section 4).
  8. Stucco (section 9), and by day a painting's own night.
  9. The sky (section 10): TURN, GROUND, BACK. Say what you cannot read.
  10. A click stills a turning picture. Take nothing else.
  11. The shimmer (section 10) and the corner (section 12).

A reader that does the first five is a YAMPAL reader, and is complete.

To write an author.

  1. Place every glyph by column and row, by program (section 7).
  2. Choose the mode: kinds of glyph, or cell by cell (section 3).
  3. For a picture from pixels, choose glyphs by brightness and colours by hue (section 8). Fine for a reader you know, safe for a stranger.
  4. Write the shadow by program. Fold repeats into runs.
  5. Decode what you wrote, count, and refuse to send if they differ.
  6. Break a long shadow before a period; two blanks in; two spaces at each line's end (section 5).
  7. Say, if it is so, that this is the first time you have sent this kind.

That is a painting of 150 cells, each said outright, and its shadow is fifteen periods. Written the classic way it is 152.

A classic shadow is a list of statements, one period to each, and it is meant to be read: by a program, and at need by a person with a finger on the slipped mark. For a photograph that list runs to hundreds of periods. The packed shadow is a second way to write the same statements, for those pictures only. It is not a new grammar. It is a container: the statements, deflated, hung under a few periods with many marks to each.

Use the classic shadow where it fits on a line or two. Pack the rest.

What marks it out. A line of nothing but periods and their marks below (and blanks), in which some period carries more than two marks. A classic slot never does, so a classic reader takes a packed line for no shadow at all, and leaves the picture plain. Nothing is mistaken for anything.

What is in it. Take every mark in order, across every period and every line of the shadow, two marks to a byte:

byte 0     1x   version 1. x bit 0: positional mode
                x bit 1: it carries a sky
the rest        raw DEFLATE (RFC 1951) of the statement bytes

The statement bytes are the classic shadow, one byte to a slot, in order, the mode switch left off: a palette position, a 2-2-2 colour, the parts of a longer colour, a run. Inflate them, write each byte back as a period with two marks, put the bare period in front if bit 0 says so, and you hold a classic shadow. Everything in sections 3 to 9 then applies as written.

With a sky. A classic shadow may wear SKYPAL's marks above its periods, and a packed one must not lose them. When bit 1 is set, what is deflated is three things in a row:

two bytes    how many statement bytes follow, low byte first
the statement bytes
the sky, as records, to the end:
  one byte   how many periods on from the last record's period
             (the first counts from the shadow's first period;
             the bare period of positional mode is a period)
  one byte   how many sky marks that period wears
  the marks  two to a byte, the first in the high half

A gap of more than 255 periods is said with a record of 255 and no marks. The reader writes each period's sky marks back after its two marks below, and then holds a classic shadow with its sky, TURN, GROUND, BACK and all.

The shape is the author's. A reader joins all the marks and does not care how they were shared out. Thirty marks to a period is the most text may carry, and it holds: forty such periods have crossed a chat and come back whole. But marks stack downward, and thirty hang five lines deep over whatever is written below. Six to a period hang one line. Use six.

Three rules of shape, so that every line can be known for what it is:

  • every period carries an even number of marks, four or more, but the last of all may be short: if it would carry two, give them to the one before;
  • a shadow longer than a line is broken as in section 5: before a period, two blanks in, two spaces at each line's end;
  • no line holds one period alone: if the last line would, bring one down from the line above.

  • It needs a deflater to write and an inflater to read. Most platforms have both. A browser has DecompressionStream('deflate-raw'); an inflater by hand is some seventy lines.
  • It cannot be written by hand, nor mended by hand.

A reader's duties. Fade a packed shadow as you fade a classic one, and no further. It is tempting to clear it away entirely, since nobody reads it; one reader did, for an evening. But a person copies a picture by sweeping a selection over it, and a hand cannot sweep to the end of what the eye cannot see: the first picture copied that way arrived with one line of its shadow, and stayed plain. What must be selected must be seen. Take nothing: the text stays as it was, and a copy of the page still carries the whole of it.

The corner. Before a person sweeps a selection they look for where to stop. Give them the corner: a one-pixel line along the right edge of the picture's block, and another along the foot of its shadow, drawn over the page in a layer of the reader's own, touching no text and taking no pointer. The foot follows the shadow's last line, not the paragraph's: in a chat the picture and the words after it often share one paragraph, and the corner must close under the picture. user1: "it shows the person the mouse-sweep or pin-swipe before engaging the action. (this is the 0th rule of GUI)". It applies to the classic shadow as much as to the packed.

// THE PACKED SHADOW
// a classic shadow -> its statement bytes
function statementsOf(shadow) {
  var out = [], cur = null, i, c, k;
  function shut() {
    if (cur && cur.length)
      out.push(cur.length === 1 ? cur[0]
        : cur[0] * 16 + cur[1]);
  }
  for (i = 0; i < shadow.length; i++) {
    c = shadow.charCodeAt(i);
    if (c === 46) { shut(); cur = []; }
    else if (cur && (k = DIG.indexOf(c)) >= 0) cur.push(k);
  }
  shut();
  return out;
}
// the sky of a classic shadow, as records
function skyRecords(shadow) {
  var out = [], cur = [], per = -1, last = 0, i, c;
  function shut() {
    var gap = per - last, k;
    if (per < 0 || !cur.length) return;
    while (gap > 255) { out.push(255, 0); gap -= 255; }
    out.push(gap, cur.length);
    for (k = 0; k < cur.length; k += 2)
      out.push(cur[k] * 16 + (cur[k + 1] || 0));
    last = per;
  }
  for (i = 0; i < shadow.length; i++) {
    c = shadow.charCodeAt(i);
    if (c === 46) { shut(); per++; cur = []; }
    else if (c >= 0x300 && c <= 0x30F && per >= 0)
      cur.push(c - 0x300);
  }
  shut();
  return out;
}
// write: marks to a period (even, 4 to 30), periods
// to a line
function packShadow(shadow, deflateRaw, marks, wide) {
  var positional = true, j;       // a first period bare below
  for (j = 1; j < shadow.length &&
       shadow.charCodeAt(j) !== 46; j++)
    if (DIG.indexOf(shadow.charCodeAt(j)) >= 0)
      positional = false;
  var st = statementsOf(shadow), sky = skyRecords(shadow);
  var body = !sky.length ? st :
    [st.length & 255, st.length >> 8].concat(st, sky);
  var bytes = [0x10 | (positional ? 1 : 0) |
    (sky.length ? 2 : 0)].concat(deflateRaw(body));
  var nib = [], per = [], lines = [], i;
  bytes.forEach(function (b) {
    nib.push(b >> 4, b & 15);
  });
  for (i = 0; i < nib.length; i += marks)
    per.push(nib.slice(i, i + marks));
  if (per.length > 1 && per[per.length - 1].length <= 2)
    per[per.length - 2] =
      per[per.length - 2].concat(per.pop());
  for (i = 0; i < per.length; i += wide)
    lines.push(per.slice(i, i + wide));
  if (lines.length > 1 &&
      lines[lines.length - 1].length < 2)
    lines[lines.length - 1].unshift(
      lines[lines.length - 2].pop());
  return lines.map(function (l) {
    return '⠀⠀' + l.map(function (p) {
      return '.' + p.map(function (v) {
        return String.fromCharCode(DIG[v]);
      }).join('');
    }).join('');
  }).join('  \n');
}
// is this text a packed shadow? (all its lines, joined)
function isPacked(text) {
  var i, c, on = 0, most = 0, periods = 0;
  for (i = 0; i < text.length; i++) {
    c = text.charCodeAt(i);
    if (c === 46) { periods++; on = 0; }
    else if (DIG.indexOf(c) >= 0) {
      if (!periods) return false;
      on++; if (on > most) most = on;
    }
    else if (c !== 32 && c !== 10 && c !== 13 &&
             c !== 0x2800 && c !== 0xA0) return false;
  }
  return most > 2;
}
// read: packed text -> a classic shadow, or a complaint
function unpackShadow(text, inflateRaw) {
  var nib = [], bytes = [], i, k, body, per = [];
  var st, sky = [], n, at = 0, idx = 0, cnt, b;
  for (i = 0; i < text.length; i++) {
    k = DIG.indexOf(text.charCodeAt(i));
    if (k >= 0) nib.push(k);
  }
  if (nib.length % 2)
    return { complaint: 'an odd number of marks, ' +
      nib.length + ': one has slipped' };
  for (i = 0; i < nib.length; i += 2)
    bytes.push(nib[i] * 16 + nib[i + 1]);
  if (bytes[0] >> 4 !== 1)
    return { complaint: 'version ' + (bytes[0] >> 4) +
      ' is not one this reader knows' };
  try { body = inflateRaw(bytes.slice(1)); }
  catch (e) {
    return { complaint: 'it would not open: ' + e };
  }
  st = body;
  if (bytes[0] & 2) {
    n = body[0] | body[1] << 8;
    st = body.slice(2, 2 + n); sky = body.slice(2 + n);
    if (st.length !== n)
      return { complaint: 'its statements are cut short' };
  }
  if (bytes[0] & 1) per.push('.');
  for (i = 0; i < st.length; i++)
    per.push('.' + String.fromCharCode(DIG[st[i] >> 4]) +
      String.fromCharCode(DIG[st[i] & 15]));
  while (at < sky.length) {
    idx += sky[at++]; cnt = sky[at++];
    if (cnt === undefined || idx >= per.length ||
        at + (cnt + 1 >> 1) > sky.length)
      return { complaint: 'its sky runs past its end' };
    for (k = 0; k < cnt; k++) {
      b = sky[at + (k >> 1)];
      per[idx] += String.fromCharCode(
        0x300 + (k % 2 ? b & 15 : b >> 4));
    }
    at += cnt + 1 >> 1;
  }
  return { shadow: per.join('') };
}
